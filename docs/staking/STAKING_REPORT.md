## 8. План дальнейших действий

### Текущий статус
- Разработан и задеплоен новый production-ready контракт с поддержкой старых стейков (`EQBNUYkjRXqAGkYFVr3oufB7vtR-Hlm2W3F6ZidM2YBZ6WYi`)
- Реализованы базовые методы для работы со старыми стейками
- Подготовлен скрипт для переноса данных со старого контракта

### Ближайшие задачи
1. Тестирование на stage (ограниченный сценарий):
   - Создание тестового стейка на предыдущем контракте
   - Перенос информации об этом стейке из базы данных в новый контракт через скрипт миграции
   - Проверка корректности маршрутизации claim запроса
   
   > **Важно**: На stage возможно протестировать только один сценарий, так как:
   > - Новый контракт уже задеплоен как production-ready
   > - Тестируем только корректность маршрутизации и обработки claim запроса
   > - Транзакция claim не будет завершена из-за отсутствия прав на NFT минт
   > - Дальнейшее тестирование (restake/withdraw) невозможно без успешного claim

2. Подготовка к production:
   - Проверка скрипта миграции на тестовом стейке
   - Подготовка списка активных стейков для миграции
   - Подготовка плана отката изменений

3. Миграция в production:
   - Добавление нового адреса контракта в доверенные на NFT контракте
   - Миграция активных стейков с помощью проверенного скрипта
   - Полное тестирование всей цепочки операций (claim → restake/withdraw)
   - Слияние ветки feature/addOldStakeLogic в master

### Критерии успешного завершения
- Тестовый сценарий на stage успешно пройден
- Скрипт миграции корректно переносит данные
- Новый адрес контракта добавлен в доверенные на NFT контракте
- Вся цепочка операций (claim → restake/withdraw) работает в production
- Балансы и награды соответствуют исходным данным

### Риски
- Минимальное тестирование на stage (только маршрутизация claim)
- Полное тестирование функционала возможно только в production
- Необходим тщательный мониторинг первых операций в production
